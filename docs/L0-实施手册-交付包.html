3模块与接口契约（关键签名）

这是"完善"最有价值的部分：把每个模块的对外签名定死，消除实现歧义。

对象存储 + 原始层（不可变）

class ObjectStore(Protocol):
    def put_bytes(self, key: str, data: bytes, content_type: str) -> str: ...
    def get_bytes(self, key: str) -> bytes: ...
    def exists(self, key: str) -> bool: ...

def raw_html_key(source_id: int, sha256: str) -> str:
    return f"raw/{source_id}/{sha256}.html"

class RawStore:                       # 只追加，无 update/delete
    def append(self, *, source_id: int, crawl_job_id: int, url: str,
               fetch_method: str, http_status: int|None=None,
               http_headers: dict|None=None, raw_entry: dict|None=None,
               raw_html: bytes|None=None, media: list|None=None,
               extra: dict|None=None) -> RawDocument: ...
        # 计算 sha256 → put 对象存储 → insert raw_documents 行

采集：RSS / 抓取 / 提取 / 去重 / 规范化

def fetch_feed(source: Source) -> list[RssEntry]            # F3.1 增量(ETag)
class FetchResult: html: bytes; status: int; headers: dict; method: str
def fetch_page(url: str, render: bool) -> FetchResult       # F4.1 httpx/Playwright

class Extracted: title: str|None; author: str|None; text: str
              published_at: datetime|None; confidence: float
def extract(html: bytes, url: str) -> Extracted             # F4.3

def url_hash(url: str) -> str                               # F5.1 规范化后
def content_hash(text: str) -> str
def simhash(text: str) -> int

class DedupResult(Enum): NEW; SAME_URL; DUPLICATE; VARIANT  # F5.2
def classify(url: str, text: str) -> tuple[DedupResult, int|None]

def build_content_item(raw: RawDocument, ex: Extracted) -> ContentItem  # F5.3 status=WAIT_FILTER

事件（事务性 outbox）+ 对上层查询契约

def emit(session, topic: str, payload: dict) -> None        # F7.1 同事务写 outbox
# relay 循环: SELECT ... WHERE published_at IS NULL → publish → mark

# query/contracts.py — 对 L1 的稳定契约
class ContentOut(BaseModel):
    id: int; canonical_url: str; title: str|None; clean_text: str
    lang: str|None; source: SourceRef; published_at: datetime|None; status: str

def list_contents(status: str, since: datetime|None,
                  limit: int, cursor: str|None) -> Page[ContentRef]   # F7.2
def get_content(content_id: int) -> ContentOut
def reprocess(scope: Scope, target_layer: str) -> int                # F7.3
契约即冻结点：上层 L1 只依赖 list_contents/get_content 与 content.ingested 事件。这些签名一旦定死，L0 内部实现可自由演进而不影响上层。

6端到端冒烟自检脚本

core_data/scripts/smoke.py：一条命令验证整条 L0 链路是否打通。

# make smoke 执行流程（伪代码）
def smoke():
    1. 导入 1 个测试源(本地 fixture RSS 或真实 feed)
    2. 同步跑一轮 crawl_source(source_id)
    3. assert raw_documents.count > 0                 # 原始层有数据
    4. assert content_items(status=WAIT_FILTER) > 0   # 规范层有实体
    5. c = get_content(first_id)
       assert c.clean_text != ""                       # 正文可取回
       assert object_store.exists(raw_html_ref)        # 原文可溯源
    6. assert outbox_events(topic="content.ingested") > 0
    7. 跑 relay，assert 事件被标记 published
    8. print 摘要: 发现/新增/去重/失败 计数 + 全链 PASS
✓ 验收 — make smoke 输出 L0 PIPELINE: PASS，且打印各阶段计数。这是 L0 "活着"的日常自检。

7完成判定（L0 DoD 复述）

  • 导入 OPML → 定时拉 RSS → 全文抓取，全链自动运行 ≥ 24h 无人工干预
  • 原始 entry / 原始 HTML / 抓取元数据完整留存可取回校验
  • content_items 状态正确、可溯源到 raw_document
  • 转载/重复正确去重，原始层不丢变体
  • 内容更新产生新版本，历史可查
  • content.ingested 不丢不重，L1 能稳定拉取
  • 可重放：能从原始层重建规范层，无需重抓
  • 覆盖率达标、CI 全绿、/healthz 正常、每次采集有 job 与指标
达成即：L0 成为独立、可信、可重放的数据底座，正式向 L1 供数。
