## 0. 背景（30 秒）

仓库 `D:\vscodefile\deepdata`，包名 `core_data`（`src/` 布局，editable 安装）。
L0 = 采集底座：采集→不可变原始层→规范化→去重→事务性 outbox（发 `content.ingested`）。
现状只支持 RSS。目标：扩成**可插拔多源平台**，支持文章型（RSS/HTML）与榜单型
（GitHub Trending、微博/抖音/百度/知乎热榜）来源，并加定时调度与界面。

**硬约束（不可违反）**
- 原始层只经 `RawStore.append()` 写入（append-only，无 update/delete）。
- `core_data` 不得导入上层（`app_l1/l2/l3`、`l1/l2/l3`）——`audit_dod` 会检查。
- `ruff check` + `mypy --strict`（py312）必须全绿；新增 `src/core_data` 代码纳入覆盖率（≥80%，scripts/* 已豁免）。
- 单测不得依赖联网：解析逻辑必须吃**本地 fixture**（沿用 `tests/fixtures/`）。

## 1. 已确认决策（实现时遵循）

1. **零数据库迁移**：榜单元数据（rank/heat/platform/tags）存入 `content_items.meta`(JSON)。
2. **新增内容状态 `TREND`**：榜单型条目 `status="TREND"`；文章型沿用现状（`WAIT_FILTER`）。`TREND` 为追加值，不改既有语义。
3. **优先级 P1→P4**；P1 的榜单样例用 **`github_trending`**（HTML，无需鉴权）。
4. **调度**：P2 先交付本地常驻脚本 `scheduler_run`；Arq cron 作为可选生产路径。
5. **html_list 选择器**：用 `lxml`（随 `trafilatura` 已间接安装）。支持 XPath（原生）与 CSS（新增依赖 `cssselect>=1.2`）。

## 2. 适配器架构

新增包 `src/core_data/ingest/adapters/`。

### 2.1 `adapters/base.py`
```python
from __future__ import annotations
from collections.abc import Iterable
from dataclasses import dataclass, field
from datetime import datetime
from typing import Any, Protocol, runtime_checkable
from core_data.db.models import Source

@dataclass(frozen=True)
class Entry:
    url: str                                  # 文章/帖子/仓库/话题链接
    title: str | None = None
    raw: dict[str, Any] = field(default_factory=dict)    # 原始 payload → raw_documents.raw_entry
    published_at: datetime | None = None
    extra: dict[str, Any] = field(default_factory=dict)  # rank/heat/platform/tags → content_items.meta

@runtime_checkable
class SourceAdapter(Protocol):
    type: str                 # 唯一类型标识，对应 sources.type
    label: str                # 界面展示名（中文）
    needs_page_fetch: bool    # True=抓正文+抽取；False=榜单条目直接入库
    config_schema: dict[str, Any]   # 类型专属参数说明，喂界面下拉
    def fetch_entries(self, source: Source) -> Iterable[Entry]: ...
```

### 2.2 `adapters/__init__.py`（注册表）
```python
_REGISTRY: dict[str, SourceAdapter] = {}
def register(adapter: SourceAdapter) -> None: _REGISTRY[adapter.type] = adapter
def get_adapter(type_: str) -> SourceAdapter:
    if type_ not in _REGISTRY: raise ValueError(f"unknown source type: {type_}")
    return _REGISTRY[type_]
def list_types() -> list[dict[str, Any]]:
    return [{"type": a.type, "label": a.label, "needs_page_fetch": a.needs_page_fetch,
             "config_schema": a.config_schema} for a in _REGISTRY.values()]
# 在模块底部 import 并 register 各内置适配器
```

## 3. pipeline 改动

`src/core_data/ingest/pipeline.py` 的 `crawl_source`：
1. `adapter = get_adapter(source.type or "rss")`（缺省回退 rss，向后兼容）。
2. `CrawlJob.kind = adapter.type`（不再写死 "rss"）。
3. 遍历 `adapter.fetch_entries(source)`：
   - 始终先 `raw_store.append(... raw_entry=entry.raw ...)`（保 append-only）。
   - `if adapter.needs_page_fetch and entry.url`: 走**现有路径**（fetch_page→extract→build_content_item）。
   - `else`: 走**新轻量路径** `build_content_item_from_entry(session, raw_doc, entry, status="TREND")`：
     直接用 `entry.title/url/extra` 造 content_item，`canonical_url=entry.url`、`meta=entry.extra`、
     `status="TREND"`；复用现有 url_hash/dedup 逻辑（同话题重复→variant）。
4. stats 增加 `trend` 计数；异常仍留 raw 证据（现有机制）。

> `build_content_item_from_entry` 新增于 `ingest/canonical.py`，复用 `url_hash/content_hash/simhash`
> 与去重，不重复实现。

## 4. 内置适配器规格

### 4.1 `rss`（迁移现有逻辑）
- `needs_page_fetch=True`；包装 `core_data.ingest.rss.fetch_feed(source.feed_url)`。
- `config_schema`: `{interval_min:int=60, render:bool=false}`。
- 行为与现状一致（回归不变）。

### 4.2 `html_list`（通用列表页）
- `needs_page_fetch=True`。
- 用 `httpx` 抓 `crawl_config.list_url`（或 `render` 时 Playwright），`lxml.html` 解析。
- `config_schema`:
  ```jsonc
  { "list_url": "https://...", "selector": "article a.title", "selector_type": "css|xpath",
    "link_attr": "href", "base_url": "https://...", "limit": 30,
    "interval_min": 60, "render": false }
  ```
- 解析：按 selector 取元素 → 绝对化链接（`urljoin(base_url, href)`）→ `Entry(url, title=text)`。
- CSS 经 `cssselect`，XPath 原生。
- **解析函数与网络分离**：`parse_list(html: bytes, cfg) -> list[Entry]`，单测吃 fixture。

### 4.3 `github_trending`（榜单样例，P1 交付）
- `needs_page_fetch=False`。
- 抓 `https://github.com/trending/{language}?since={since}`（`language` 可空），`lxml` 解析。
- 每仓库 → `Entry(url=repo_url, title="owner/name",
  extra={rank, stars, stars_today, language, description, platform:"github"})`。
- `config_schema`: `{language:str="", since:"daily|weekly|monthly"="daily", interval_min:int=180}`。
- 单测吃 `tests/fixtures/html/github_trending.html`。

### 4.4 平台适配器（P4，扩展位）
`baidu_hot`/`zhihu_hot`/`weibo_hot`（JSON 端点，`weibo_hot` 支持 `crawl_config.cookie`）、
`douyin_hot`/`xiaohongshu`（留接口 + `NotImplementedError("需 API/cookie，见文档")` + config_schema）。
均 `needs_page_fetch=False`，解析函数吃 fixture 单测。

## 5. 调度（P2）

### 5.1 本地常驻脚本 `src/core_data/scripts/scheduler_run.py`
- CLI：`--tick-sec 60`、`--once`、`--render`、`--host-relay`（是否同时 relay）。
- 循环：`due_sources(session)` → 逐源 `crawl_source` → `session.commit()` →（可选）relay outbox → `sleep(tick)`。
- 复用现有 `scheduler.due_sources()`（已按 `crawl_config.interval_min` 判定）。
- 心跳：每 tick 更新一个轻量状态（建议写 `.runtime/scheduler-heartbeat.json`：`{last_tick, due, crawled}`），供界面读。
- 异常隔离：单源失败不中断整轮，记日志。

### 5.2 Arq cron（可选生产）
`workers/ingestion/worker.py` 增 `crawl_due` 任务 + `cron(crawl_due, minute=set(range(0,60,5)))`。需 Redis 常驻。

### 5.3 `next_run_at`
= `source_health.last_attempt_at + interval_min`，由 `_status()` 计算给界面。
